## 1. 评估总览

音频编解码器是 TTS 系统的核心组件，负责音频信号的编码（压缩）与解码（重建）。当前项目 VoxCPM2 引擎使用 AudioVAE V2 作为默认编解码器，IndexTTS2 引擎使用内置声码器。随着项目多引擎扩展，需要评估替代编解码器方案以提升质量、降低资源消耗或支持更多场景。

### 1.1 评估维度

| 维度 | 说明 |
|------|------|
| **架构概览** | 核心网络结构与关键技术 |
| **音频质量** | 重建精度、MOS 分、主观听感 |
| **推理性能** | RTF（Real-Time Factor）、延迟、CPU/GPU 兼容性 |
| **显存需求** | 模型参数量、推理时 VRAM 占用 |
| **集成复杂度** | 代码侵入性、依赖兼容性、API 适配难度 |
| **许可证合规** | 开源许可证类型与商用风险 |
| **推荐等级** | adopt（采用）/ evaluate（评估）/ defer（推迟） |

### 1.2 编解码器分类

```
编解码器
├── 神经编解码器（Neural Codec）— 学习音频压缩表示
│   ├── AudioVAE V2 — 连续 VAE 潜在空间
│   ├── DAC — RVQ 离散量化
│   └── S3Tokenizer — 语言无关语音分词
│
└── 神经声码器（Neural Vocoder）— 频谱/潜在表示 → 波形
    ├── Vocos — ConvNeXt + ISTFT（轻量）
    ├── BigVGAN — 大规模 HiFi-GAN 变体
    ├── HiFT-GAN / NSF+ISTFT — F0 条件化 GAN
    ├── UnivNet — 多周期判别器 GAN
    └── WaveRNN — 自回归 GRU 声码器
```

## 2. AudioVAE V2（VoxCPM）

### 2.1 架构概览

AudioVAE V2 是 VoxCPM2 的核心音频编解码器，采用**非对称编码/解码设计**实现 16kHz 输入 → 48kHz 输出的超分辨率合成。

| 参数 | 编码器 | 解码器 |
|------|--------|--------|
| 输入采样率 | 16,000 Hz | — |
| 输出采样率 | — | 48,000 Hz |
| 下采样倍率 | 640x（rates: [2,5,8,8]） | — |
| 上采样倍率 | — | 1920x（rates: [8,6,5,2,2,2]） |
| 潜在维度 | 64 维 | 64 维 |
| 编码器维度 | 128 | — |
| 解码器维度 | — | 2048 |
| 帧率 | 25 Hz（16000/640） | — |
| 采样率条件边界 | — | [20000, 30000, 40000] |

**关键技术**：

1. **因果卷积**（CausalConv1d / CausalTransposeConv1d）：确保流式解码的因果性，支持实时增量解码
2. **Snake 激活函数**：`@torch.jit.script` 优化的 Snake 激活，带来 1.4x 推理加速
3. **采样率条件层**（SampleRateConditionLayer）：通过 Embedding 条件化不同输出采样率，单一模型支持多采样率输出
4. **非对称设计**：编码器轻量（128 dim）用于快速特征提取，解码器重型（2048 dim）用于高保真重建

### 2.2 优势

- 与 VoxCPM2 深度集成，无需额外适配
- 非对称设计：轻量编码 + 高保真解码
- 因果卷积天然支持流式推理
- Snake 激活函数优化推理速度
- 采样率条件层支持 16kHz/24kHz/48kHz 灵活输出
- 48kHz 输出达到录音室级音质

### 2.3 劣势

- 与 VoxCPM2 强耦合，不可独立替换
- 解码器 2048 维度较大，推理显存占用偏高
- 不产出离散 token，无法用于 LM-based 离散量化方案
- 模型重训练成本高

### 2.4 资源需求

| 资源 | 估算值 |
|------|--------|
| 模型参数量 | ~150M（编码器 ~20M + 解码器 ~130M） |
| 推理 VRAM | ~1.5 GB（含 KV Cache） |
| 推理 RTF | ~0.05（GPU），~0.3（CPU） |

### 2.5 集成复杂度

| 维度 | 评估 |
|------|------|
| 代码侵入性 | 低 — 已集成 |
| 依赖兼容性 | 无 — 原生依赖 |
| API 适配 | 无 — 已适配 |

### 2.6 推荐等级

| 等级 | 说明 |
|------|------|
| **adopt** | 当前 VoxCPM2 默认编解码器，保持现状。作为未来 VoxCPM2 升级路径持续跟踪 AudioVAE V2 迭代。 |

## 3. DAC（Descript Audio Codec）

### 3.1 架构概览

DAC（Descript Audio Codec）是 Descript 公司开发的神经音频编解码器，采用 **Residual Vector Quantization（RVQ）** 作为核心量化策略，被视为 EnCodec 的替代方案。Fish Speech 在其 Dual-AR 架构中验证了 DAC 的优越性。

| 参数 | 数值 |
|------|------|
| 采样率 | 44.1 kHz |
| 帧率 | ~86 Hz（下采样 512x） |
| RVQ 层数 | 9 层 |
| Codebook 大小 | 1024 |
| 量化码率 | ~8 kbps |
| 潜在维度 | 1024 |

**关键技术**：

1. **残差向量量化（RVQ）**：多层量化逐级逼近原始信号，每层量化前一层的残差
2. **Snake 激活**：与 AudioVAE V2 类似，使用 Snake 激活替代 ReLU/GELU
3. **多尺度判别器**：多尺度 STFT 判别器 + 多周期判别器，提升频谱和周期性建模
4. **VQ 码本学习**：指数移动平均（EMA）更新码本，避免码本崩塌

### 3.2 优势

- Fish Speech 验证质量优于 EnCodec（Seed-TTS Eval WER 最佳）
- 离散 token 输出，天然适配 LM-based TTS（VALL-E 系架构）
- RVQ 多层量化提供可变码率：高层捕获语义，低层捕获声学细节
- Snake 激活提升推理效率
- 社区活跃，持续迭代

### 3.3 劣势

- 量化过程引入信息损失，连续空间音质上限高于离散量化
- 9 层 RVQ 自回归解码推理较慢
- 与 VoxCPM2 的连续潜在空间不兼容，替换需重构整个管线
- 仅支持编码/解码，无内置超分辨率能力

### 3.4 资源需求

| 资源 | 估算值 |
|------|--------|
| 模型参数量 | ~70M |
| 推理 VRAM | ~0.8 GB |
| 推理 RTF | ~0.08（GPU），~0.5（CPU） |

### 3.5 集成复杂度

| 维度 | 评估 |
|------|------|
| 代码侵入性 | 高 — 需替换整个编解码管线 |
| 依赖兼容性 | 中 — descript-audio-codec 独立包 |
| API 适配 | 高 — 需重写 VAE encoder/decoder 接口 |

### 3.6 推荐等级

| 等级 | 说明 |
|------|------|
| **evaluate** | 推荐作为未来编解码器替代方案评估。若新增 LM-based 引擎（如 Fish Speech 风格），DAC 是首选量化方案。对现有 VoxCPM2 管线暂不替换。 |

## 4. S3Tokenizer

### 4.1 架构概览

S3Tokenizer 是 Resemble AI 为 Chatterbox 开发的**语言无关语音分词器**，支持流式处理。其核心设计理念是提供统一的跨语言语音 token 表示，消除不同语言间的分词差异。

| 参数 | 数值 |
|------|------|
| 输入采样率 | 16/24/44.1 kHz |
| 输出 token 率 | ~50 Hz |
| 量化方式 | RVQ（6 层） |
| 语言支持 | 23+ 种语言 |
| 流式支持 | 原生支持 |

**关键技术**：

1. **语言无关设计**：不依赖语言特定的文本前端，纯声学驱动
2. **流式编码**：支持增量式 token 生成，适配实时场景
3. **多采样率输入**：自动重采样到内部处理采样率
4. **与 CAMPPlus 说话人编码器协同**：双编码器融合提升说话人相似度

### 4.2 优势

- 语言无关，完美适配多语言 TTS 场景
- 原生流式支持，延迟极低
- Chatterbox V3 验证跨语言能力（23+ 种语言）
- 与说话人编码器（CAMPPlus）协同设计
- MIT 许可证，商用友好

### 4.3 劣势

- 相对较新，社区验证不如 DAC/EnCodec 充分
- 音质不如 AudioVAE V2 的连续潜在空间
- 仅作为分词器使用，需搭配独立声码器
- 文档较少，集成调试成本较高

### 4.4 资源需求

| 资源 | 估算值 |
|------|--------|
| 模型参数量 | ~40M |
| 推理 VRAM | ~0.5 GB |
| 推理 RTF | ~0.03（GPU），~0.2（CPU） |

### 4.5 集成复杂度

| 维度 | 评估 |
|------|------|
| 代码侵入性 | 中 — 可作为独立分词模块引入 |
| 依赖兼容性 | 低 — s3tokenizer 独立 pip 包 |
| API 适配 | 中 — 需适配 tokenizer 接口 |

### 4.6 推荐等级

| 等级 | 说明 |
|------|------|
| **evaluate** | 适合多语言 TTS 场景评估。若项目未来引入 Chatterbox 或类似多语言引擎，S3Tokenizer 是首选语音分词方案。建议在 P2 阶段进行集成验证。 |

## 5. Vocos

### 5.1 架构概览

Vocos 是一种轻量级神经声码器，采用 **ConvNeXt + ISTFT（逆短时傅里叶变换）** 架构。ChatTTS 在其生产管线中验证了 Vocos 的实用性：仅 82M 参数即可实现 CPU 实时推理。

| 参数 | 数值 |
|------|------|
| 模型参数量 | 82M |
| 输入 | Mel 频谱图 |
| 输出采样率 | 24 kHz |
| 骨干网络 | ConvNeXt（4 层 FFC 块） |
| 解码头 | ISTFTHead（逆短时傅里叶变换） |
| 推理方式 | 单次前向（非自回归） |

**关键技术**：

1. **ConvNeXt 骨干**：借鉴视觉领域的 ConvNeXt 模块，使用 7x1 深度可分离卷积 + LayerNorm + GELU
2. **ISTFT 解码头**：直接预测 STFT 复数谱（幅度 + 相位），通过 ISTFT 重建波形，避免传统上采样伪影
3. **全频带处理**：FFC（Fast Fourier Convolution）块实现全局频率感受野
4. **非自回归解码**：单次前向推理，RTF 极低

### 5.2 优势

- 轻量高效：82M 参数，CPU 实时推理
- ISTFT 解码避免相位伪影，音质优于传统 GAN 声码器
- 非自回归，推理延迟极低
- ChatTTS 生产验证，成熟可靠
- 依赖简单，仅需 torch + torchaudio
- MIT 许可证

### 5.3 劣势

- 仅作为声码器（Mel → 波形），不含编码器
- 固定 24kHz 输出，不支持 48kHz 高保真场景
- 频谱输入依赖上游 Mel 特征提取质量
- 对超长音频可能需要分段处理

### 5.4 资源需求

| 资源 | 估算值 |
|------|--------|
| 模型参数量 | 82M |
| 推理 VRAM | ~0.4 GB |
| 推理 RTF | ~0.02（GPU），~0.8（CPU，实时） |

### 5.5 集成复杂度

| 维度 | 评估 |
|------|------|
| 代码侵入性 | 低 — 独立声码器模块 |
| 依赖兼容性 | 低 — 无额外依赖 |
| API 适配 | 低 — 标准 Mel 输入接口 |

### 5.6 推荐等级

| 等级 | 说明 |
|------|------|
| **adopt** | **轻量部署首选**。推荐作为低配设备和 CPU 推理场景的默认声码器。可替代 HiFi-GAN 作为 IndexTTS2 的后端声码器，大幅降低显存需求。建议 P1 阶段集成验证。 |

## 6. BigVGAN

### 6.1 架构概览

BigVGAN 是大规模 HiFi-GAN 的改进变体，作为 GPT-SoVITS v3 的 CFM（Conditional Flow Matching）声码器后端使用。通过增大模型规模和改进训练策略，在音质上超越标准 HiFi-GAN。

| 参数 | 数值 |
|------|------|
| 模型参数量 | ~120M（大版本） |
| 输入 | Mel 频谱图 |
| 输出采样率 | 24/44.1 kHz |
| 生成器 | 放大版 HiFi-GAN Generator |
| 判别器 | Multi-Scale + Multi-Period |

**关键技术**：

1. **大规模 HiFi-GAN**：增大 Generator 容量，更多的上采样层和残差块
2. **改进训练策略**：引入频谱判别损失 + 感知损失
3. **CFM 集成**：GPT-SoVITS v3 在 Mel 空间执行 Flow Matching，BigVGAN 负责最终波形生成
4. **多采样率支持**：提供 24kHz 和 44.1kHz 预训练模型

### 6.2 优势

- 音质优于标准 HiFi-GAN
- GPT-SoVITS v3 生产验证
- 多采样率预训练模型可用
- Apache 2.0 许可证

### 6.3 劣势

- 参数量大于 Vocos（120M vs 82M），推理更重
- 仍基于 GAN 生成器，存在相位估计问题
- 不如 Vocos 的 ISTFT 方案在 CPU 上高效
- 集成需要额外适配 CFM → Mel → BigVGAN 管线

### 6.4 资源需求

| 资源 | 估算值 |
|------|--------|
| 模型参数量 | ~120M |
| 推理 VRAM | ~0.6 GB |
| 推理 RTF | ~0.04（GPU），~1.2（CPU） |

### 6.5 集成复杂度

| 维度 | 评估 |
|------|------|
| 代码侵入性 | 中 — 需要独立声码器模块 + CFM 管线适配 |
| 依赖兼容性 | 低 — 仅需 torch |
| API 适配 | 中 — 需适配 Mel 输入 + 采样率处理 |

### 6.6 推荐等级

| 等级 | 说明 |
|------|------|
| **evaluate** | 音质优秀但比 Vocos 更重。仅在需要 44.1kHz 高保真输出时考虑。若 Vocos 验证满足需求则无需引入 BigVGAN。 |

## 7. HiFT-GAN / NSF+ISTFT

### 7.1 架构概览

HiFT-GAN 和 NSF+ISTFT 是 GPT-SoVITS v2/v4 使用的声码器后端，属于 F0 条件化 GAN 声码器家族。已在生产环境中长期验证。

| 参数 | HiFT-GAN | NSF+ISTFT |
|------|----------|-----------|
| 核心思路 | HiFi-GAN + F0 预测器 | Neural Source Filter + ISTFT |
| F0 条件化 | 显式 F0 输入 | 显式 F0 输入 |
| 解码方式 | 转置卷积上采样 | NSF 谐波生成 + ISTFT |
| 输出采样率 | 32/44.1 kHz | 44.1 kHz |
| 参数量 | ~80M | ~60M |

**关键技术**：

1. **F0 条件化**：将基频（Fundamental Frequency）信息作为条件输入，确保生成音频的音高与目标一致
2. **HiFT-GAN**：在 HiFi-GAN 基础上增加 F0 预测器，联合优化声码器和音高预测
3. **NSF+ISTFT**：Neural Source Filter 生成谐波激励，通过 ISTFT 精确重建波形

### 7.2 优势

- GPT-SoVITS v2/v4 生产验证，稳定性高
- F0 条件化确保音高准确性
- NSF+ISTFT 相位质量优于传统 GAN
- 模型轻量（60-80M 参数）

### 7.3 劣势

- 架构较老，性能上限不如 Vocos/BigVGAN
- F0 提取增加管线复杂度（需额外 F0 提取器）
- GPT-SoVITS 特定接口，通用性较差
- 维护活跃度下降

### 7.4 资源需求

| 资源 | 估算值 |
|------|--------|
| 模型参数量 | 60-80M |
| 推理 VRAM | ~0.3-0.5 GB |
| 推理 RTF | ~0.03（GPU），~0.8（CPU） |

### 7.5 集成复杂度

| 维度 | 评估 |
|------|------|
| 代码侵入性 | 中 — 需 F0 提取器 + 声码器协同 |
| 依赖兼容性 | 中 — 依赖 GPT-SoVITS 工具链 |
| API 适配 | 高 — 接口与 GPT-SoVITS 绑定 |

### 7.6 推荐等级

| 等级 | 说明 |
|------|------|
| **defer** | 已在生产环境验证但架构老化。仅在集成 GPT-SoVITS 引擎时随引擎自带使用，不推荐作为独立声码器引入。 |

## 8. UnivNet

### 8.1 架构概览

UnivNet 是一种通用神经声码器，设计目标是在多种说话人和采样率下都能生成高质量语音。Tortoise-TTS 使用 UnivNet 作为默认声码器。

| 参数 | 数值 |
|------|------|
| 输入 | Mel 频谱图 |
| 输出采样率 | 22.05/24 kHz |
| 生成器 | HiFi-GAN 风格上采样网络 |
| 判别器 | 多尺度 STFT 判别器 |
| 参数量 | ~30M（轻量版）/ ~60M（标准版） |

**关键技术**：

1. **多尺度 STFT 判别器**：在多个时间尺度上分析频谱，捕获不同粒度的声学特征
2. **LVC（Location-Variable Convolution）**：条件化卷积核随输入动态变化，提升说话人适应性
3. **通用设计**：不针对特定说话人训练，开箱即用

### 8.2 优势

- 通用性强，不限定说话人
- 多尺度判别器频谱建模优秀
- Tortoise-TTS 生产验证
- 模型轻量，推理快速
- Apache 2.0 许可证

### 8.3 劣势

- 非当前 SOTA，音质上限不如 Vocos/BigVGAN
- 不支持高采样率（最高 24kHz）
- 通用性以牺牲说话人特化质量为代价
- 社区活跃度一般

### 8.4 资源需求

| 资源 | 估算值 |
|------|--------|
| 模型参数量 | 30-60M |
| 推理 VRAM | ~0.2-0.4 GB |
| 推理 RTF | ~0.02（GPU），~0.6（CPU） |

### 8.5 集成复杂度

| 维度 | 评估 |
|------|------|
| 代码侵入性 | 低 — 独立声码器 |
| 依赖兼容性 | 低 — 标准 torch 依赖 |
| API 适配 | 低 — 标准 Mel 输入 |

### 8.6 推荐等级

| 等级 | 说明 |
|------|------|
| **defer** | 灵活但非 SOTA。若集成 Tortoise-TTS 引擎则随引擎自带使用。作为独立声码器方案，Vocos 是更优选择。 |

## 9. WaveRNN

### 9.1 架构概览

WaveRNN 是经典的神经声码器，由 Real-Time-Voice-Cloning 项目使用。采用双层 GRU + 全连接层，逐样本自回归生成波形。

| 参数 | 数值 |
|------|------|
| 输入 | Mel 频谱图 + 说话人嵌入 |
| 输出采样率 | 16 kHz |
| 核心网络 | 2 层 GRU（1024 hidden） + 2 层 FC |
| 生成方式 | 逐样本自回归 |
| 参数量 | ~20M |

**关键技术**：

1. **双 softmax 输出**：将 16-bit 样本拆分为高低 8-bit，减少每步分类空间
2. **fold_with_overlap 批量推理**：将长序列折叠为重叠批量，GPU 并行加速
3. **等功率交叉淡入淡出**：消除片段边界伪影

### 9.2 优势

- 极轻量（~20M 参数）
- 模型简单，易于理解和调试
- MIT 许可证
- 批量推理可实现 > 1kHz 生成速率

### 9.3 劣势

- 逐样本自回归，理论最低 RTF >> 1（CPU 无法实时）
- 16kHz 采样率过低，不满足现代音质需求
- 音质远不如 Vocos/BigVGAN 等非自回归声码器
- 已被业界淘汰，无持续维护

### 9.4 资源需求

| 资源 | 估算值 |
|------|--------|
| 模型参数量 | ~20M |
| 推理 VRAM | ~0.2 GB |
| 推理 RTF | ~0.05（GPU 批量），> 5.0（CPU 逐样本） |

### 9.5 集成复杂度

| 维度 | 评估 |
|------|------|
| 代码侵入性 | 中 — 需适配自回归推理循环 |
| 依赖兼容性 | 低 — 无额外依赖 |
| API 适配 | 高 — 非标准逐样本接口 |

### 9.6 推荐等级

| 等级 | 说明 |
|------|------|
| **defer** | **不推荐集成**。逐样本自回归对现代用例太慢，16kHz 输出无法满足音质需求。仅保留代码参考价值（批量推理技巧、交叉淡入淡出策略）。 |

### 11.4 技术风险提示

1. **采样率差异陷阱**：16kHz/22050Hz/24kHz/44100Hz/48kHz 混用会导致音频质量问题，所有编解码器输出必须经过统一重采样管线
2. **依赖冲突风险**：DAC（descript-audio-codec）、S3Tokenizer 等独立包可能与现有 PyTorch/transformers 版本冲突，需虚拟环境隔离
3. **torch.compile 兼容性**：Triton 不完全支持 Windows，部分编解码器的编译加速需 CPU/PyTorch 回退方案
4. **显存叠加风险**：多编解码器同时驻留显存可能导致 OOM，需严格管理编解码器生命周期
